# Spending limits

Flyway V007 through V011 are required. V010 removes subcategory limits. Pre-production V011 permanently removes all period overrides, dependent override references and dated setting revisions by dropping their tables. It does not infer category defaults from overrides. Current main-category settings, their permanent references, categories, ledger data and audit records remain intact. The migrations run once at backend startup; restoring an older backup and starting the updated backend reapplies pending cleanup.

Main spending categories have one current limit, entered as monthly or yearly within category CRUD. Monthly × 12 gives yearly; yearly ÷ 12 gives monthly. The category list shows both. Source amounts accept zero and up to twenty integer/eight fractional digits. Backend derivation uses BigDecimal, with yearly division HALF_UP at eight fractional places; displays use two decimals. Converting display units retains the canonical source until the amount is edited. No limit is different from zero.

Every selected month/year uses the current category limit, including past periods. A monthly report uses its monthly allowance and that month’s net spending; a yearly report uses the full yearly allowance and that year’s net spending. Current activity stops at the business date (APP_BUSINESS_TIME_ZONE, default Europe/Zurich); future activity is zero, without prorating limits. Main-category comparisons include direct and immediate child assignments. Refunds reduce spending and can make it negative. Transfers, income, opening balances and deleted operations are excluded. Archived activity remains included.

Spending (#/spending, with #/planning compatibility alias) is read-only for limits. Manage limit links select the main category in Categories. Period overrides, copying, reset controls and editable monthly breakdowns are removed, together with all /api/v1/budgets routes. GET/PUT /api/v1/budget-settings remain. Supporting activity uses /api/v1/spending/activity and needs no limit: 50 operations per page in ledger order, with account links. Reports and activity are owner-scoped no-store repeatable-read snapshots.

Category saves check category, setting and preferences versions and commit details/limits/audit together. Stale requests return 412; failed requests retain input. Archived categories may edit an existing limit in either input unit or select No limit, but cannot enable a new limit. Permanent current-setting references still prevent category deletion or structure changes after clearing a limit.

Owners explicitly select a default ISO 4217 currency in Settings; none is inferred. Foreign activity stays separate without FX. Changing default currency requires confirmation when limits exist and clears all current limits, including their use in historical reports. Owners must enter limits again. Unchanged currency saves do not reset anything; stale versions or audit failures roll back the complete change.

The chart shows expenses before refunds, using main-category inclusive totals plus uncategorized, counting each expense once. Refund-only periods retain table rows. Parent expansion shows direct and child breakdowns; Show all categories reveals zero-activity rows. Keyboard-accessible legends focus table branches. No dependencies, jobs, caches or services are added; imports and recurring expectations remain deferred.
