# Spending budgets

Flyway V007 and V008 are required. Back up spending_budgets, budget_category_history, budget_settings, budget_setting_revisions and budget_setting_category_history with the full database. Existing limits remain explicit period exceptions; no normal defaults are inferred. Never truncate history to unlock a category. No services, dependencies, jobs or caches are added.

APP_BUSINESS_TIME_ZONE (default Europe/Zurich) determines the current business date. Month starts are day 1; year starts are January 1. Compact Categories cards set one normal monthly/yearly limit per category/currency or No limit. A save affects the current period and future periods; dated revisions preserve earlier periods. Exceptions remain independent and survive mode changes. Zero is an actual allowance, unlike No limit.

Spending (`#/spending`, legacy `#/planning`) edits exceptions beside each effective limit. Current budget-period editors offer Only this period (default) or Make this the normal limit. Promotion saves the normal setting and removes that same exception atomically. Past/future editors only change that period. Confirmed Use normal limit removes an exception and restores the applicable default. No default means no limit.

Monthly comparisons prefer monthly exceptions/defaults, otherwise annual exceptions/defaults with year-to-date spending through the selected month, capped today. Yearly comparisons prefer annual exceptions/defaults, otherwise sum monthly allowances through the current month, including its full allowance. Monthly rolled-up yearly totals are read-only; Edit months opens twelve monthly editors. Future months do not accrue. Spending used displays its usage dates separately from report-period expenses/refunds/net.

Amounts accept zero and up to 20 integer/eight fractional digits. Exact decimal strings are preserved; percentage alone uses two-place HALF_UP and is unavailable for zero limits. Refunds can exceed purchases. Currency, category ownership and archived restrictions are enforced server-side. Parent comparisons include direct spending and immediate children; coverage counts each operation once without summing overlapping allowances. Uncategorized spending is unbudgeted.

Normal-setting and effective-limit requests carry expected setting/exception ID-version references, including null for expected absence. A stale reference returns 412 and commits nothing; failed forms retain input. Legacy exception APIs retain quoted If-Match requirements (428 missing, 412 stale). Missing/unowned resources return 404; unavailable branches return 409. Changes, history and audit snapshots commit together. Archived existing same-frequency settings and exceptions remain editable; new limits are blocked. No limit/reset preserve permanent history.

Copy period exceptions is collapsed in Spending. Sources must share one period and canonical target must differ. Normal settings are never copied. Stale/unowned sources reject the whole request; existing targets and archived branches are explicitly skipped. Supporting activity needs no limit and paginates 50 operations in ledger order with account links. Reads are owner-scoped repeatable-read snapshots with no-store.

The expense pie uses inclusive top-level expenses plus uncategorized expenses before refunds, counting each expense once. Refund-only periods retain table rows and an explanatory chart state. Parents expand into direct and child activity; Show all categories reveals inactive rows. Keyboard-accessible legends focus the corresponding branch. Income, transfers, opening balances and deleted operations never count. Archived accounts/categories remain included. Imports and recurring expectations remain deferred.
