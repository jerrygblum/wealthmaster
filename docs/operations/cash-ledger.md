# Cash ledger

Flyway V005 creates operations, signed movements and permanent account references. It leaves opening balances unchanged and does not manufacture transactions. Back up PostgreSQL before upgrading; restore the complete database, including ledger history and audit events, rather than individual tables.

Configure `APP_BUSINESS_TIME_ZONE` (default `Europe/Zurich`) consistently across deployments. It controls the business date for current balances and report timestamps; audit timestamps remain UTC. Invalid zone names fail startup. Existing date-only values are never converted through a time zone.

Balances are opening balance plus all non-deleted cash movements through the business date, including transactions before account opening. The opening amount is counted once; opening date does not filter transactions. Future-dated transactions, refunds and transfers can be recorded and appear in activity as Scheduled; they start affecting current balances on their transaction date. Transaction and value dates allow any valid date in years 1–9999, including before account opening. Value dates do not control balance inclusion. Investment balances exclude holdings. Credit-card debt is negative; overpayments are positive. Refunds reduce spending. Transfers do not count as spending or income, even for credit-card repayments. Negative balances are allowed. Activity is entered in native currency without rounding, with up to 20 integer digits and eight decimal places.

Archived activity is readable. Restore every currently affected account before adding, correcting or deleting activity. Correcting a transfer changes both sides; deleting it removes both sides from balances. History permanently prevents account deletion and financial setup edits, even after all entries have been deleted or moved elsewhere. Audit snapshots retain prior values; they are sensitive financial data and belong in protected backups, never application logs or public fixtures.

Writes require a fresh CSRF token and authenticated, MFA-authorized session. Edits/deletions require a quoted operation version in `If-Match`; 412 means reload, 428 means supply a version, 409 means restore affected accounts. Missing and foreign resources both return 404. Do not blindly retry a create after an ambiguous connection loss; reload activity first to avoid duplicates. No idempotency keys or duplicate detection are implemented in this slice.

Verification uses synthetic, disposable databases. Backend integration tests accept `-Dtest.database.url`, `-Dtest.database.username`, and `-Dtest.database.password` when Docker is unavailable. Browser fixtures require a database name ending `_e2e`; set `DB_URL`, `DB_USER`, `DB_PASSWORD`, and run `npm run test:e2e` with `E2E_PROFILE=dev`, then `prod`. Never target a production database with these tests.
